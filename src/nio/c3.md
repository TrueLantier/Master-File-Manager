Hay dos cambios independientes: `Partes` reemplaza toda la lógica de extensión, y los cuatro bucles masivos se alimentan de una lista ya materializada.

## 1. Integrar `Partes`

Ponlo en su propio archivo, `nio/renombrar/Partes.java`. Luego tres cambios.

**`NioRenombrar`:** `renombrarElemento` queda así, y borras `renombrarConSufijo`, `tienePuntos` y `NÚMERO_PUNTOS`:

```java
public static void renombrarElemento(String rutaElemento, String nuevoNombre) {
    if (Validador.validar(rutaElemento, Operaciones.RENOMBRAR)) {
        return;
    }
    Path fuente = Path.of(rutaElemento);
    String nombre = ProcesarCadenas.nombreNuevoConExtensión(fuente, nuevoNombre);
    renombrar(fuente, fuente.resolveSibling(nombre));
}
```

**`ProcesarCadenas`:** los dos métodos que hoy hacen `lastIndexOf(".")` delegan en `Partes`:

```java
public static String nombreNuevoConSufijo(Path fuente, String sufijo) {
    Partes p = Partes.de(fuente);
    return p.base() + sufijo + p.extension();
}

public static String nombreNuevoConExtensión(Path fuente, String nuevoNombre) {
    return nuevoNombre + Partes.de(fuente).extension();
}
```

En `construirNombreManga`, reemplaza `nombreElemento` por `Partes.de(elemento).base()`. Tanto el `PATRON.matcher(...)` como `encontrarPalabraClave(...)` deben trabajar sobre la base, no sobre el nombre con extensión.

Esto arregla de paso `agregarSufijo` en carpetas con punto, como `v1.2`, que hoy queda como `v1_x.2`.

Dos decisiones que puedes querer revisar:
- **Doble extensión:** al borrar `tienePuntos`, `algo.tar.gz` se interpreta como base `algo.tar` y extensión `.gz`. Renombrarlo manualmente a `nuevo` daría `nuevo.gz`, y se pierde el `.tar`. Antes lo rechazabas con error. Si quieres conservar esa protección, puede ser un caso especial en `Partes` (`base.endsWith(".tar")` entra a la extensión) o una lista corta de extensiones compuestas.
- **`quitarCadena`:** hoy hace `replace` sobre el nombre completo, así que quitar `cbz` se come la extensión. Decide si debe operar solo sobre `base()`.

## 2. ¿Cambiar todos los `DirectoryStream`?

Sí, en los cuatro métodos masivos (`renombrarMangas`, `agregarTodoPrefijo`, `agregarTodoSufijo`, `quitarTodoCadena`), y en los de prefijo y sufijo importa más que en el de mangas. POSIX deja sin especificar si `readdir` devuelve un archivo que cambió después de abrir el directorio. Si `a.txt` reaparece como `pre_a.txt`, tu código le agrega el prefijo otra vez: `pre_pre_a.txt`. Con mangas, un segundo paso produce el mismo nombre, así que el daño es menor. Con prefijo y sufijo, no.

No hace falta abandonar `DirectoryStream`. Basta con vaciarlo en una lista y cerrarlo **antes** de renombrar nada:

```java
private static List<Path> listar(String rutaElementos) throws IOException {
    List<Path> elementos = new ArrayList<>();
    try (DirectoryStream<Path> ds = Files.newDirectoryStream(Path.of(rutaElementos))) {
        for (Path p : ds) {
            elementos.add(p);
        }
    }
    Collections.sort(elementos);   // orden determinista
    return elementos;
}
```

Cada método cambia solo el `for`:

```java
try {
    for (Path elemento : listar(rutaElementos)) {
        agregarPrefijo(elemento.toString(), prefijo);
    }
} catch (Exception e) {
    MensajesError.agregarError(rutaElementos, Operaciones.RENOMBRAR, e.getMessage(), e);
}
```

En `renombrarMangas`, saca de paso `ProcesarCadenas.agregarPalabrasClave(palabrasClave)` fuera del bucle, para que no se ejecute una vez por archivo.

Esto es el mínimo. La fase de plan con vista previa para detectar colisiones va encima, y `listar` será su primer paso, así que no tiras nada.
