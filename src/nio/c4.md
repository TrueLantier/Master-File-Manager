Mejoró bastante: `listar` hace lo que debe, `Partes` está integrada, quitaste `ATOMIC_MOVE`, `quitarCadena` ya mira el nombre y no la ruta, y `encontrarPalabraClave` quedó bien (varias claves, `quote`, Unicode, límites de palabra). Pero el código nuevo de `construirNombreManga` introduce un fallo que lo rompe por completo. Orden de prioridades:

## P0: hoy rompe el flujo de mangas

**1. `matcher.group(3)` lanza `IndexOutOfBoundsException`.** `PATRON` solo tiene 2 grupos, así que cualquier archivo con un número revienta ahí. El `catch` de `renombrarMangas` envuelve todo el `for`: la excepción se reporta una vez y el lote se detiene en el primer archivo con número. Hay tres problemas más en ese bloque:
- `númeroTres != ""` compara referencias, no contenido.
- Si lo corriges, la rama "más de tres números" devuelve `elemento.getFileName().toString()`, que ya incluye la extensión. `renombrarElemento` le añade la extensión otra vez y obtienes `Naruto 2 vol 3.cbz.cbz`.
- El `while` siempre retorna en la primera vuelta, así que es un `if`.

Para detectar ambigüedad no necesitas un tercer grupo: tras leer el primer match, pregunta si hay otro. Y "no aplica" se expresa con `Optional.empty()`, no con un nombre:

```java
public static Optional<String> construirNombreManga(Path elemento, List<String> claves) {
    String nombreManga = elemento.getParent().getFileName().toString();
    String base = Partes.de(elemento).base();
    String clave = encontrarPalabraClave(base, claves);

    Matcher m = PATRON.matcher(base);
    if (!m.find()) {
        // sin número: con clave se conserva ("Epílogo Naruto"); sin clave, no aplica
        return clave.isEmpty() ? Optional.empty() : Optional.of(clave + nombreManga);
    }
    String uno = m.group(1);
    String dos = m.group(2);
    if (m.find()) {                       // un segundo número distinto: ambiguo
        MensajesError.agregarError(elemento.toString(), Operaciones.RENOMBRAR,
                "Más de un número en el nombre; no se renombra.", new IllegalArgumentException());
        return Optional.empty();
    }
    String capítulo = (dos == null) ? uno : uno + "-" + dos;
    return Optional.of(clave + capítulo + " " + nombreManga);
}
```

En `renombrarMangas`: `construirNombreManga(elemento, claves).ifPresent(n -> renombrarElemento(elemento.toString(), n));`.

**2. Reactiva `if (fuente.equals(destino)) return;`.** Sin eso, todo archivo que ya está bien nombrado entra a `Validador.sobrescribir` y te pregunta si se sobrescribe contra sí mismo. `Files.move` sobre el mismo archivo es no-op; el problema es el `Files.exists` previo.

**3. El fallback `(sin número) N` se vuelve a leer como capítulo.** El nombre `Naruto (sin número) 2` contiene un dígito. En la siguiente ejecución, `PATRON` lo toma como capítulo 2 y el archivo pasa a ser `2 Naruto`, posiblemente chocando con el capítulo real 2. Además, `num` es estático: no se reinicia entre carpetas ni ejecuciones, y nada garantiza que el nombre sea único. Mi recomendación es la del código de arriba: con clave se conserva, sin clave se deja intacto y se reporta. Si dos archivos acaban con el mismo nombre, eso lo resuelve el plan de colisiones (P1), no un contador global.

## P1: antes de usarlo en colecciones reales

**4. Colisiones.** Sigue pendiente, y ahora que `Files.move` usa `REPLACE_EXISTING`, un "sí" en el prompt reemplaza el archivo sin más. La versión mínima: antes de mover nada, arma un `Map<Path, List<Path>>` de destino a orígenes, y si un destino tiene más de un origen, repórtalos y sáltalos en vez de preguntar. La vista previa puede venir después.

**5. Claves como estado estático.** `agregarPalabrasClave` acumula entre llamadas, y las duplicadas salen en el nombre: pasar `"Extra"`, que ya está por defecto, produce `Extra Extra 5 Naruto`. Pásalas como parámetro:

```java
private static final List<String> CLAVES_POR_DEFECTO = List.of("Final", "Extra", "Especial", "Epílogo");

public static List<String> clavesConExtras(String... extras) {
    Set<String> todas = new LinkedHashSet<>(CLAVES_POR_DEFECTO);
    Collections.addAll(todas, extras);
    return new ArrayList<>(todas);
}
```

`encontrarPalabraClave` recibe la lista, y `renombrarMangas` la construye una vez por llamada.

**6. `try/catch` por elemento** dentro del `for` de los cuatro métodos masivos. Con eso, el punto 1 habría costado un archivo y no el lote entero.
